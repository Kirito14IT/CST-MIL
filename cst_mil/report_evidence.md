## 一、任务内容：可直接写入报告的事实清单

### 1.1 任务范围梳理

- 研究内容：轻量级短文本隐主题发现与会话级风险判别。
- 研究对象：当前阶段先处理纯文本；虽然总体目标可扩展到即时通讯和社交媒体，首轮实验严格限定为 SCCD 的真实微博原帖—评论会话。

- 说明：SCCD 的评论细粒度标签在构造时使用了 LLM 辅助的人在回路流程，但这不等于当前 CST-MIL 使用大语言模型。当前模型训练只使用会话级标签，评论级标签仅用于测试阶段的证据定位评价。

### 1.3 LCCC-base 的核验结果

官方来源：

- [CDial-GPT/LCCC 作者仓库](https://github.com/thu-coai/CDial-GPT)
- [LCCC 原论文](https://arxiv.org/abs/2008.03946)
- [thu-coai/lccc 数据集卡](https://huggingface.co/datasets/thu-coai/lccc)

可以确认：

- LCCC-base 是清华 CoAI 团队发布的大规模中文开放域短对话语料，原始对话来自微博，规模约 682 万段。
- 每条记录的公开结构是按顺序排列的 `dialog` 字符串列表；它适合中文对话读取、分词、普通对话建模和无监督主题展示。
- 官方将仅含 2 个语句的记录称为单轮对话，含 2 个以上语句的记录称为多轮对话；LCCC-base 多轮部分平均每段约 3.86 个语句。这是“每段对话的发言数”，不是“一轮有多个人”。
- 官方清洗主动过滤脏字脏词、敏感内容、特殊字符、颜表情、语法异常和上下文不相关对话；LCCC-base 比 LCCC-large 清洗更严格。
- 发布结构没有网络欺凌/危险标签、稳定用户身份、完整回复关系或群成员结构，因此不能直接评价会话级危险识别。

推荐写法：

> LCCC-base 是质量较好的大规模中文开放域对话语料，但不适合作为本项目危险会话检测的主评测集。原因不是其总体质量差，而是它缺少危险标签和真实多人会话结构，并且清洗过程会主动削弱本项目需要识别的敏感、攻击性和噪声内容。

不可写成：

- “LCCC-base 是劣质数据集”或“完全不可用”。
- “LCCC-base 是带真实成员身份的多人群聊”。
- “已经通过模型实验证明 LCCC-base 不可用”。当前结论来自任务—数据匹配分析。

### 1.4 SCCD 的核验结果及选择理由

官方来源：

- [STAIR-BUPT/SCCD 作者仓库](https://github.com/STAIR-BUPT/SCCD)及[本实验固定提交](https://github.com/STAIR-BUPT/SCCD/tree/cf4015b802cabd651885211dc382152c1a270c31)
- [COLING 2025 论文页面](https://aclanthology.org/2025.coling-main.639/)
- [论文 PDF](https://aclanthology.org/2025.coling-main.639.pdf)

官方可确认事实：

- SCCD 是以微博为来源的中文会话级网络欺凌数据集。
- 一段会话由一条源微博及后续评论等信息构成，而不是微信/QQ 式持续群聊。
- 数据包含 677 个会话，其中 354 个 CB、323 个 Non-CB；共 38,999 条评论，其中 9,805 条标为 CB。
- 会话具有 `CB / Non-CB` 标签，CB 会话另有轻度、中度、重度等级。
- 评论字段包括评论 ID、所属微博 ID、匿名用户 ID、相对原帖的评论时间、评论内容、所回复评论的 ID，以及五类细粒度标注。因此可按 `post_id` 组成会话，按 `comment_time` 排序，并用 `to_id` 恢复部分回复边。
- `to_id` 为空表示该评论不是对另一条评论的直接回复；这不等于它不属于该微博会话。
- 评论级标注包括是否网络欺凌、显式/隐式表达、是否讽刺、个人/群体目标和群体类别。评论标注采用 LLM 辅助的人在回路流程，并执行抽样核验；会话标签由人工标注。
- 仓库根目录没有明确独立 LICENSE。报告宜称“公开发布/公开可访问的数据集”，不要直接称为许可证完备的“开源数据集”；本地研究可以记录来源，但公开再分发前应向作者确认授权。

为什么 SCCD 比 LCCC-base 更适合当前项目：

1. SCCD 的领域标签与最终确定的“网络欺凌、辱骂、言语暴力”一致。
2. SCCD 同时提供会话标签和评论级标签，可分别评估会话风险判别与证据评论定位。
3. `post_id`、`comment_time` 和 `to_id` 支持构造有时间顺序、含部分回复结构的真实微博会话。
4. CB 会话比例为 52.3%，会话层面接近平衡，适合首轮二分类可行性实验。
5. 单条评论多数很短，能够直接检验短文本稀疏条件下的轻量级方法。

### 1.6 CST-MIL 方法工作可以如何写入“任务内容”

在正式结果生成前，可以先写方法事实，不能写性能结论：

- 提出 CST-MIL（Conversation Structure and Topic-aware Multiple-Instance Learning），由字符风险通道、弱监督多实例学习、MiniBatchNMF 隐主题和会话级线性分类器组成。
- 字符 2–5 gram 用于降低中文分词错误、错别字和变体表达的影响。
- 训练只使用会话级标签；正会话内通过三轮自训练选择高风险评论候选，避免把正会话中的所有普通评论都强行视作危险评论。
- NMF 提取会话主题分布、相邻消息主题变化和回复边主题差异。
- 会话级线性分类器聚合评论风险、隐主题和回复结构，输出风险概率；Top-3 评论和主题关键词作为解释。
- 整个方法使用 CPU 稀疏特征，不调用大语言模型、预训练编码器或 GPU。

## 二、作出的决定和收获：推荐事实与措辞

### 2.1 已确定的研究决策

| 决策项 | 最终决定 | 决策依据 |
|---|---|---|
| 研究领域 | 网络欺凌、辱骂、言语暴力 | 与 SCCD 标签和当前 Word 中危险定义一致 |
| 主数据集 | SCCD | 有真实微博会话、会话级风险标签、评论级证据标签和部分回复结构 |
| 样本单位 | 一条微博原帖及其按时间排序的全部评论 | 与 SCCD 论文的 session 定义一致，也符合“聊天记录/会话为单位”要求 |
| 首轮任务 | 会话级 `CB / Non-CB` 二分类 | 现有标签足以支持；不虚构赌博、毒品、诈骗等类别 |
| 首轮监督 | 训练只使用会话标签 | 避免把细粒度评论标签当作模型输入；评论标签仅用于证据评价 |
| 方法路线 | 轻量字符特征 + 隐主题 + 回复结构 + MIL | 同时回应短文本稀疏、会话级判别和证据定位需求 |
| 计算约束 | CPU、稀疏矩阵、线性模型 | 与“不依赖大语言模型、便宜、速度不慢”的目标一致 |

### 2.2 可写入报告的主要收获

1. **数据集质量必须相对于任务判断。** LCCC-base 对普通中文对话研究有价值，但缺少危险标签和成员/回复结构，因此不能承担危险会话主评测；这不是对其整体质量的否定。
2. **“多人微博会话”和“即时通讯群聊”必须区分。** SCCD 保留匿名用户 ID、时间和部分回复关系，可称真实微博多人互动会话；它没有群成员名单和统一群聊时间线，不能称微信/QQ群聊。
3. **主题发现和风险判别不是同一个输出。** LDA、BTM、GSDMM、NMF、BERTopic 原生输出主题、簇或主题分布；要评价 `CB / Non-CB`，必须增加统一的会话聚合和轻量分类层。
4. **短文本不能简单整段拼接后宣称问题已解决。** 单条消息能够体现极端稀疏性，整段会话可提供上下文但会混合多个主题；后续基线应同时比较单条消息、固定窗口和完整会话。
5. **可解释性应落到原文证据。** 主题词只能说明语料结构，不能单独证明危险；最终解释需要同时给出会话风险、原始评论证据和回复上下文。

推荐总结句：

> 本阶段完成了研究领域、数据集、会话单位和评价目标的收敛：以 SCCD 中真实微博原帖—评论会话为研究对象，聚焦网络欺凌、辱骂和言语暴力，以会话级 CB/Non-CB 判别为主任务，并把评论级标签保留为证据定位评价。该选择比 LCCC-base 更贴合当前危险会话任务，但研究结论仍不能直接外推到微信、QQ 或其他即时通讯群聊。

## 三、存在的问题及后续改进措施

### 3.1 当前阶段必须报告的问题

- **平台外推有限：** SCCD 是微博树状评论会话，不是即时通讯群聊；模型可能学习微博表达和采样偏差。
- **风险范围有限：** 标签覆盖网络欺凌及其细粒度表达，不支持直接评价赌博、毒品、电信诈骗或有组织暴力策划。
- **发布版噪声被削弱：** URL、emoji、`@USER` 等被作者清洗，无法完整模拟真实群聊噪声。
- **动态性尚未验证：** 静态随机切分不能证明增量学习或新暗语适应能力。
- **授权边界不清：** SCCD 仓库没有明确独立 LICENSE，不能随代码重新打包发布原始 CSV。
- **数据质量需处理：** 存在孤立评论、重复评论 ID、一个标签冲突 ID 和无评论会话，清洗规则与数量必须保存在运行日志中。
- **评论标签并非全部独立人工逐条初标：** 评论标注含 LLM 辅助的人在回路过程；使用这些标签评价证据定位时应说明标注来源。
- **首轮实验规模有限：** 300 会话、一个固定划分、一次训练只能作为可行性结果；bootstrap 区间只描述固定测试集抽样不确定性，不能替代多随机种子训练。
- **本轮没有基线性能比较：** 当前不能宣称 CST-MIL 优于 LDA、BTM、GSDMM、NMF 或 BERTopic。

### 3.2 五种基线对 SCCD 的适用性与适配矩阵

总体判断：五种方法都**不能以原始形态直接完成 SCCD 会话级风险判别**，但没有一种必须完全排除。它们可作为主题/聚类特征提取器，经统一的会话构造、聚合和分类头后形成公平基线。

SCCD 原论文确实报告了 CNN、LSTM、BERT、RoBERTa、GPT-4 等评论级/会话级检测基线，但没有报告本任务指定的 LDA、BTM、GSDMM、NMF、BERTopic。论文采用 7:3 训练/测试划分并对多数模型运行 5 次；这些公开结果既不能替代五种主题基线适配，也不能与本轮 60/20/20、一次训练的可行性结果直接横比。

| 方法 | 原生输出及直接适用程度 | SCCD 建议输入 | 必需适配 | 适配后仍存在的限制 |
|---|---|---|---|---|
| LDA | 文档主题分布；单条极短评论上直接适用性较弱 | 完整会话、固定窗口；单条评论仅作稀疏性对照 | 中文分词；只在训练集拟合词表/主题；将窗口主题分布聚合为会话向量；增加统一 Logistic Regression 分类头 | 词袋模型忽略消息顺序、父子回复和新词变体；整段会话会混合多个局部主题 |
| BTM | 语料级 biterm 主题，专为短文本缓解共现稀疏；不能直接给风险标签 | 单条评论或固定窗口 | 统一分词；对验证/测试文本执行主题推断；聚合消息主题为会话向量；增加相同分类头 | 原生模型仍不利用时间和回复结构；批量主题固定后对快速新词演化支持有限 |
| GSDMM | 每篇短文档一个簇/主题；适合单主题短文本，不适合把长会话直接假设为单主题 | 单条评论或固定窗口，不建议整段会话作为唯一单主题文档 | 编写 held-out 文档的冻结簇后验分配；按会话汇总簇直方图；增加相同分类头；多随机种子报告 Gibbs 波动 | 一文档一主题假设难覆盖多主题会话；不利用顺序/回复；作者 Java 仓库缺少 LICENSE |
| NMF | 非负文档主题向量；轻量、可解释，是最直接的 CPU 对照之一 | 词级 TF-IDF 的完整会话和固定窗口 | 训练集拟合 TF-IDF/NMF；窗口主题聚合；增加相同分类头；固定初始化和主题数搜索规则 | 静态词表仍受新暗语影响；无原生时间或回复建模；原作者无官方维护代码 |
| BERTopic | 嵌入—降维—密度聚类—c-TF-IDF 主题；可处理短文本，但成本最高，原生仍非风险分类器 | 评论或固定窗口；完整长会话需控制输入长度 | 固定中文/多语言嵌入模型；训练集拟合主题模型；处理 `-1` 离群主题；聚合主题/概率并接相同分类头 | 使用预训练嵌入，资源和依赖高于前四者；不原生利用回复树；CPU 可运行但速度可能较慢 |

需要纠正 Word 中可能被直接复制的过度概括：

- BERTopic **不要求** GPU，GPU 只是可选加速。
- BERTopic 基础 c-TF-IDF 主题词来自原语料，**不会天然生成幻觉**；只有额外接入生成式模型命名或总结主题时才有生成幻觉问题。
- NMF 是否支持在线更新及其稳定性取决于具体实现、向量化和初始化，不能无实验写成“在线版本不稳定”。
- 主题模型的 topic ID 不能直接当作危险/正常标签；必须通过训练集标签学习风险映射。

### 3.3 下一阶段统一基线协议

1. 复用同一 SCCD 清洗结果、`post_id` 会话划分和随机种子；任何主题词表、聚类器和阈值都只能在训练/验证集确定。
2. 为五种方法统一实现三种输入单位：单条评论、固定消息窗口、完整会话。不得让不同方法使用不同样本边界却直接比较。
3. 所有方法输出统一为会话级主题特征，再接同一种带类别平衡的轻量 Logistic Regression；另设“仅主题/簇特征”与“加入通用结构特征”的分层比较。
4. 主指标统一为 macro-F1、CB Recall、CB F1、PR-AUC、ROC-AUC、Accuracy、训练/推理时间和峰值内存；主题质量另报 NPMI/topic diversity。二元 CB 标签不是主题真值，NMI/ARI 不应作为主任务核心指标。
5. 完整实验扩展到全部可用 SCCD 会话，至少运行 5 个随机种子，报告均值、标准差和置信区间；BERTopic额外报告 `-1` 离群比例和有效覆盖率。
6. 增加 CST-MIL 消融：去除字符通道、去除 NMF 主题、去除回复结构、去除 MIL 选择，并验证每个组件对准确性、召回率和效率的贡献。
7. 增加时间顺序或流式更新实验后，才能评价“快速演化”；若 SCCD 时间跨度不足，需要另建具有时间戳和新暗语变化的补充数据。
8. 对用户/事件近重复和平台线索做泄漏检查；严禁把评论级标签、讽刺/表达类别、用户 ID、点赞量直接当作纯文本主实验特征。
