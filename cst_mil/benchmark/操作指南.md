入口会自动把实验进程及其子进程限定在同一组 4 个逻辑 CPU，并设置数值库线程参数，无需修改你的 PowerShell 或系统全局设置。操作系统限制及观测到的最大 CPU 亲和性宽度写入每个运行的 `TRAINED.json`；后台辅助线程可以存在，但不能额外占用其他逻辑 CPU。若无法落实该限制或检测到子进程超限，程序会拒绝提交结果。

## 3. 先处理 300 个，再继续剩余会话

例如，先让 CST-MIL 累计完成前 300 个会话的预测：

```powershell
uv run --frozen --group benchmark cst-bench run --suite full677 --method cst_mil --limit 300 --resume
```

之后继续到全量 677 个会话：

```powershell
uv run --frozen --group benchmark cst-bench run --suite full677 --method cst_mil --limit all --resume
```

其他方法只需替换 `--method` 后的名称，续跑语义相同。

`--limit` 表示**累计完成的推理会话数**，不是训练集大小，也不是本次新增处理数量。第一条命令首次执行时，仍先用全部 406 个训练会话拟合模型，用 135 个验证会话选择阈值，然后预测前 300 个会话。第二条命令加载同一个已保存模型，跳过已经完成的会话，继续余下 377 个。

推理顺序是训练区、验证区、测试区。因此前 300 个全量预测都属于训练区，此时没有正式测试集指标。只有完成测试区后，才能解释测试集性能；不能把全部 677 个会话的输出混成“测试准确率”。

每个完整会话独立、原子保存。中断时的行为为：

- 已存在且校验通过的 `TRAINED.json` 和 `model.joblib`：恢复时不重新训练。
- 训练阶段中断、尚无完整训练提交：重新执行同一命令，会在新的 `assets/attempt_N/` 中重做未完成训练，保留之前的原生训练资料。
- 推理阶段中断：已经完整保存的会话不重复预测；尚未提交完成的会话会重新处理。
- 全部完成后再执行相同命令：不会重新训练或增加重复会话；会重新检查结果并更新汇总状态。

## 5. 指纹错误与安全重试

若提示 `config/source/environment/data changed` 或 `Model fingerprint mismatch`，说明当前代码、数据、依赖或模型与已冻结运行不一致。此时不能通过修改指纹、删除 manifest 或覆盖模型强行续跑。

先查看对应目录的最新 `error_*.json`，确认是否误改了代码或环境。恢复到原运行的源码快照和锁定依赖后，可以重新执行原来的 `--resume` 命令。普通中断且指纹未变时，直接执行原命令即可。

若确实要修复算法、替换数据或升级依赖，应保留完整原运行目录、日志和源码快照，登记独立的新实验版本，在独立工作副本或新增的运行命名空间中从头训练。当前 CLI 没有通用 `--new-run` 参数；`--revision r0/r1/r2/r3` 用于预注册的 CST-MIL 小实验修订，不能用来给 baseline 任意更名或绕过已有运行。新版本不能把旧模型的已完成会话混入新模型结果。

## 6. 新版多主题输出如何理解

新版 CST-MIL 对连续消息窗口学习主题，输出数量可变的 `topics[]`。每个主题带抽取式标题、关键词、支持消息、连续片段、发言人标识及原文证据。一条消息可以支持多个主题，同一主题可以在多个不连续片段出现。

这些是语料中学习的讨论主题，并非预设“网络欺凌、辱骂、言语暴力”三个类别。会话风险监督仍是 SCCD 的 `CB / Non-CB` 二分类。`topic_strength` 表示主题强度，`risk_score` 表示风险分数，不能把它们当作已验证校准的置信度。没有输出主题也可能是词表覆盖不足，不能直接解释成“安全”。

程序接口 `predict_session(model, session, messages)` 可以接收追加消息后的完整会话，在**固定模型**下重新输出主题及位置；这不会增量训练主题参数或风险分类器。基准实验中的数据清单保持冻结，因此这种会话更新应作为独立推理输出，不能修改已提交基准会话后继续混写同一次实验。

SCCD 没有真实主题数量和边界标签。0/1/2/3 主题构造案例用于工程检查；真实数据主题结果使用一致性、多样性、消息覆盖率等代理指标评价，不报告没有标注支持的“主题数量准确率”。
